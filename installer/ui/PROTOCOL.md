# Протокол Inno <-> WXQSetupUI

Inno Setup остаётся движком: проверка прав, поиск игры и версии, копирование, реестр, ярлыки, `WXQTool.exe` (`--progress`), удаление. Единственное видимое окно — `WXQSetupUI.exe`; окно мастера Inno скрыто (прозрачное, без мыши, без фокуса, вне панели задач ещё до первого показа). Обмен — два файла в защищённой папке `%ProgramData%\WXQ-setup-<guid>` (см. последний раздел).

## Запуск и жизнь окна

- Мастер извлекает `WXQSetupUI.exe` в `{tmp}` (`dontcopy`), копирует в защищённую папку, сверяет SHA-256 копии и запускает оттуда `WXQSetupUI.exe --dir "<папка обмена>" --token <токен> --parent <pid мастера>`. Токен — буквы и цифры, 4-40 знаков; мастер берёт его из `CoCreateGuid` (32 шестнадцатеричных знака, не угадывается по PID и времени); папка — абсолютный существующий путь. Другие аргументы при рабочем запуске не нужны.
- Шрифты окно распаковывает в `<папка exe>\fonts` (в рабочем режиме это защищённая папка установщика), всегда перезаписывая файлы. Если эта папка, подпапка или файл - точка повторного разбора (junction, символьная ссылка), шрифты не грузятся и текст остаётся на Segoe UI. `%TEMP%` используется только в `--demo` и `--render`.
- Процесс-родитель (`--parent`) окно получает один раз при старте и дальше проверяет `HasExited` у этого объекта (повторно использованный PID его не обманет). Родителя нет при старте - выход с кодом 2.
- Окно создаёт именованный мьютекс `Local\WXQSetupUI-<токен>` после первого кадра. Мастер ждёт его до 10 секунд; не появился — остаются стандартные страницы Inno (окно мастера даже не скрывалось), а в `state.json` пишется `screen: "quit"`, чтобы запоздавшее окно закрылось само.
- Мастер опрашивает мьютекс каждые 50 мс. Мьютекс исчез без команды `close` (окно упало, процесс убит) — мастер возвращает своему окну прозрачность и показывает стандартные страницы. Идущая запись в игру при этом не прерывается: окно мастера появляется на странице, где установка остановилась.
- Окно само закрывается, когда видит `screen: "quit"` (пишется в `DeinitializeSetup`), когда нет процесса `--parent` и через 1,2 с после `close` или `launch`.
- Тихий режим (`/SILENT`, `/VERYSILENT`) окно не запускает. `/NOUI=1` отключает окно и в обычном режиме (стандартные страницы Inno).

## state.json: Inno -> UI (UI опрашивает раз в 100 мс по `rev`)

Файл пишется целиком в `state.json.tmp` и подменяется `MoveFileExW(REPLACE_EXISTING)` с повтором до ~100 мс; кодировка UTF-8 с BOM (окно его отбрасывает; без BOM тоже читается), одна строка JSON. Окно открывает файл с `FileShare.ReadWrite | Delete`, не читает файл больше 64 КБ, а оборванный, пустой, повреждённый файл, чужую структуру, неизвестный `screen`, `rev` не больше прежнего пропускает без изменения экрана (`WXQSetupUI.exe --selftest`).

```json
{"rev":12,"screen":"progress","op":"install","percent":47.5,"step":4,"step_state":"run","detail":"Файл 13 из 84",
 "file":"Globalindex/GlobalIndexPrime.data","eta":"осталось ~3 мин","done_bytes":126763044,"total_bytes":171674428,"state":"running",
 "launcher_on":true,"launcher_available":true,"launcher_installed":false,"has_launcher_shortcut":true,
 "failure_code":"","failure_message":"","failed_before_write":true,"fail_kind":"install","note":"","interrupted":false,
 "can_remove":false,"translation_version":"0.6.3","game_version":"1.6.0.1",
 "update_enabled":true,"update_state":"available","update_version":"0.6.4","update_message":"Доступна новая версия перевода",
 "update_done_bytes":0,"update_total_bytes":0}
```

| Поле | Значения | Смысл |
|---|---|---|
| `rev` | целое, растёт | версия файла; окно применяет состояние, только если `rev` больше прежнего |
| `screen` | `welcome` `progress` `done` `fail` `installed` `removed`; `quit` | экран; `quit` — Inno закончил, окно закрывается |
| `op` | `install` `remove` | что идёт на экране прогресса (у `remove` нет списка шагов) |
| `percent` | 0..100 | общий прогресс (окно ограничивает 0..100 и плавно доводит число) |
| `step` | 0..5; 6 | шаг: поиск игры, проверка версии, резервная копия, запись, проверка результата; 6 — все готовы; 0 — шаги не идут |
| `step_state` | `run` `fail` | у `fail` маркер текущего шага красный |
| `detail`, `file`, `eta` | строки | подпись шага (`Файл N из M`), короткое имя файла (пакет/имя), оценка времени |
| `stage` | `""` `close` | `close` - помощник закрывает мешающие игру и лаунчер (`WXQTool --close`): `detail` = «Закрываю игру и лаунчер: имена.exe», `file` пуст; окно показывает эту строку и пояснение «Закрываю игру и лаунчер…». Любое другое значение окно считает пустым. Поле необязательное (нет поля - `""`) |
| `done_bytes`, `total_bytes` | целые | объём текущего шага; `total_bytes = 0` — неизвестен, «X из Y» не показывается |
| `state` | `idle` `running` `finished` `failed` | при `running` окно не шлёт команд и не закрывается |
| `launcher_available` | bool | в сборке есть русский лаунчер: показывать блок «Компоненты / Русский лаунчер» |
| `launcher_on` | bool | галочка «Русский лаунчер» (окно берёт её из состояния только при входе на экран; по умолчанию включена, когда `launcher_available`; `/LAUNCHERRU=0` выключает) |
| `launcher_installed` | bool | лаунчер поставлен (текст «Игра и лаунчер переведены» только при `true`) |
| `has_launcher_shortcut` | bool | есть что запускать (ярлык оригинального или русского лаунчера); иначе «Запустить игру» недоступна |
| `failure_code`, `failure_message` | строки | код и человеческий текст отказа от `WXQTool` |
| `failed_before_write` | bool | `true`: «Ничего не повреждено»; `false`: предложить «Назад» и «Удалить перевод» для отката |
| `fail_kind` | `install` `remove` | какая операция не удалась |
| `note` | строка | заметка на экране «Перевод удалён» (например, о резервных копиях другой папки игры) |
| `can_remove`, `interrupted` | bool | на экране приветствия есть «Удалить перевод»; прошлая установка не завершилась (экран `installed`, главное действие — откат) |
| `translation_version`, `game_version` | строки | для экрана «Перевод уже установлен» |
| `update_enabled` | bool; по умолчанию `false` | включить карточку обновлений в шапке; отсутствующее поле сохраняет совместимость со старым мастером |
| `update_state` | `none` `checking` `current` `available` `downloading` `ready` `handoff` `failed` | состояние обновления; отсутствующее или неизвестное значение — `none` |
| `update_version` | строка, до 80 знаков | доступная или проверенная версия установщика; не заменяет `translation_version`, полученную от установленного перевода |
| `update_message` | строка, до 280 знаков | пояснение проверки или ошибки; управляющие и невидимые знаки удаляются, пробелы нормализуются. Это обычный текст, не ссылка и не разметка |
| `update_done_bytes`, `update_total_bytes` | целые 0..Int64.MaxValue | объём скачивания: отрицательный и нечисловой — 0, переполнение ограничивается Int64.MaxValue; если итог известен, `done` не больше `total`. При `total = 0` итог неизвестен, счётчик `done` сохраняется |

### Обновления в окне установщика

Мастер начинает проверку при запуске асинхронно. Окно само не обращается в сеть и не запускает программы: оно отображает состояние и передаёт команды мастеру. Отдельных окон уведомлений и значка русификатора в трее нет. Карточка находится в правой части шапки и не перекрывает установку, откат или выбор компонентов. `available` и `ready` остаются видимыми до изменения состояния мастером; при появлении карточка плавно входит в окно, если системные анимации включены.

- `none`: кнопка «Проверить»; `checking`: проверка уже идёт, установка и откат доступны.
- `current`: компактное «У вас актуальная версия» и повторная проверка.
- `available`, `ready`: версия и кнопка «Обновить», рядом кнопка повторной проверки. Длинная версия сокращается многоточием; полный текст и `update_message` доступны в подсказке.
- `downloading`: объём и полоса прогресса в той же карточке. Пока итог неизвестен, показывается «Размер загрузки уточняется».
- `handoff`: «Установщик перезапустится…»; окно ждёт завершения мастера и штатного `screen: "quit"`.
- `failed`: понятное пояснение и «Проверить ещё раз». При недоступной сети установка и откат остаются доступны.

После клика «Обновить» окно сразу защищает команду от повторного клика и блокирует действия с игрой, не ожидая следующего файла состояния. Во время `downloading` и `handoff` недоступны установка, откат, запуск игры, выбор компонентов, возврат и выбор папки. Закрыть установщик можно: мастер прекращает работу своего загрузчика при завершении. Во время записи файлов игры (`state: "running"` или экран `progress`) обновление и закрытие недоступны. После отказа обновления действия с игрой снова доступны.

После обновления самой игры восстановление перевода выполняется через этот установщик: дойти до главного меню игры, закрыть игру и открыть русификатор для переустановки. Фонового восстановления после закрытия игры нет.

### Закрытие игры и лаунчера (0.6.1)

Помощник сам закрывает мешающие процессы; окно ничего не спрашивает и ничего не запускает, только показывает ход. Параметр `--close all` передаёт мастер (`CloseParam`) при установке из окна, явном `/VERYSILENT` и удалении из «Установки и удаления программ»; без параметра помощник только отказывает кодом `running`. Проверка и скачивание обновления не закрывают игру или лаунчер. При продолжении установки после обновления действуют те же правила, что при обычной установке из окна. Помощник пишет в файл `--progress` фазу: `phase=closing`, `item=<имена.exe через запятую>`; после закрытия `phase` возвращается к имени команды. Мастер переводит это в `stage:"close"` + `detail` (см. таблицу); подпись шага после закрытия возвращается прежней. Формат файла прогресса не менялся (семь ключей). Правила выбора процессов и режимы — `WXQTool.cs`, класс `Closer`, и `README.md` (раздел «Закрытие игры и лаунчера»).

Пояснения этапов (суть + «Подробнее») окно берёт из своего кода (`MainView.StageInfo`) по `step`, `op` и `stage`; в протоколе для них полей нет. Совет «Что делать» на экране сбоя - `MainView.FixHint` по `failure_code`.

## commands.jsonl: UI -> Inno (одна JSON-строка на команду, дописывается)

```json
{"seq":3,"cmd":"install","options":{"launcher":true}}
{"seq":4,"cmd":"close"}
{"seq":5,"cmd":"checkupdate"}
{"seq":6,"cmd":"update"}
```

Окно дописывает строку одним вызовом `Write` (при занятом файле до 20 повторов по 25 мс). Мастер каждые 50 мс читает файл целиком (не больше 64 КБ) и берёт только строки, законченные переводом строки.

Строка принимается, только если совпала ровно с одним из двух видов: `{"seq":N,"cmd":"X"}` или `{"seq":N,"cmd":"X","options":{"launcher":true|false}}`, где `N` - целое от 1 без плюса и нулей впереди, длиной до 9 знаков, и `N` больше последнего принятого. Всё остальное (лишние поля, пробелы, другой порядок, длина более 120 знаков, неизвестная команда) отвергается с записью в журнал и ничего не делает.

| `cmd` | Принимается на экране | Что делает Inno |
|---|---|---|
| `install` | `welcome`, `installed` (не при `interrupted`) | запомнить `options.launcher` и начать установку (то же, что кнопка «Далее» мастера) |
| `options` | `welcome`, `installed` | запомнить `options.launcher`, больше ничего |
| `remove` | `welcome`, `installed`, если есть что удалять | откат по резервным копиям (`WXQTool restore`) и снятие русского лаунчера; приложение русификатора остаётся для повторной установки и обновлений, полное удаление — через настройки Windows |
| `launch` | `done` | запустить оригинальный или русский лаунчер от имени обычного пользователя и закрыть мастер |
| `back` | `fail`, `removed` | вернуться на приветствие с повторной проверкой установленного состояния; на экране `removed` это кнопка «Установить снова», без автоматической записи в игру |
| `pickgame` | `fail` при установке с `failure_code` `game_not_found`, `game_ambiguous` или `game_missing` | Inno показывает системный диалог выбора папки (`BrowseForFolder`), выбранный путь проверяет помощник (`find --game`: `WXQ.exe`, `WXQ_Data`, `Package`). Принятая папка запоминается на повторную попытку и мастер возвращается на приветствие; отвергнутая не запоминается, причина показывается на экране сбоя. Путь в команде не передаётся |
| `close` | любой, кроме `running` | закрыть мастер |
| `checkupdate` | `welcome`, `installed`, `done`, `fail`, `removed`, когда поддержка включена и проверка/скачивание не идут | асинхронно проверить обновления; без `options`, путей или произвольного текста |
| `update` | те же экраны, при `update_state: "available"` или `"ready"` | скачать и применить обновление либо применить уже скачанное; без `options`, путей или произвольного текста |

Окно не передаёт путей, адресов и произвольного текста: игру и её папку Inno определяет сам (`WXQTool find`; при неудаче папку выбирает пользователь командой `pickgame`, диалог показывает сам Setup), ярлык лаунчера берёт из ответа помощника, запускает только через `ShellExecAsOriginalUser`. Подтверждение удаления целиком внутри окна: команда `remove` уходит только после «Удалить».

Ссылки блока «Поддержать» и «Сообщество» окно открывает только по клику и только из белого списка (boosty.to/eg01stgames, t.me/eg01stgame, discord.gg/Zf69zsm5dQ, vk.com/ego1stgames, youtube.com/@egoist_games_one): `https`, без порта, логина, запроса и якоря, регистр пути важен; открываются через `explorer.exe`, чтобы браузер запускала обычная оболочка пользователя, а не окно установщика с правами администратора.

## Проверка без Inno

`WXQSetupUI.exe --selftest` — разбор состояния (оборванный и битый файл, `rev`, `quit`, пределы), состояния обновления и совместимость отсутствующих полей, Int64-пределы, очистка текста, блокировка команд и повторного клика, белый список ссылок, формат команд и дописывание (код выхода 0). `--demo` — окно с панелью переключения экранов и фиктивным прогрессом. `--render <папка> [--dpi 96|144|192]` — PNG всех экранов, включая проверку, доступное обновление установленного перевода, скачивание с известным/неизвестным размером, отказ, готовое обновление и перезапуск. Самопроверка и рендеры не показывают окна. Тестовая сборка (`build_ui.py --test-build`) понимает `WXQ_UI_AUTOPILOT` (сценарий нажатий, например `welcome=toggle;welcome=install;done=close`) и `WXQ_UI_SHOTS` (папка снимков); в релизном exe этого кода нет. Тестовая сборка мастера принимает `/UISTATEDIR=<папка>` (точный путь защищённой папки, чтобы тест читал `state.json` и `commands.jsonl`; ключи `/SECPARENT`, `/UIEXESHA`, `/TOOLSHA` — в последнем разделе) и `/UIEXE=<exe>` (другой исполняемый файл вместо встроенного окна, например несуществующий для проверки отката).

## Защищённая папка установщика (`{tmp}` не используется)

Установщик идёт с `requireAdministrator`, а `{tmp}` (`%TEMP%\is-*.tmp`) создаётся в профиле того же пользователя, куда имеет доступ и его обычный (не повышенный) процесс. Он мог бы между извлечением и запуском подменить `WXQSetupUI.exe`, `WXQTool.exe`, файлы данных или файлы обмена и получить выполнение с правами администратора. Поэтому повышенный мастер ничего не запускает и не читает как команду из `{tmp}`.

Порядок (код — `SecPrepare` в `InitializeSetup`, до первого окна; `WXQRussian.iss`):

1. Родитель - сам `%ProgramData%`: должен существовать и не быть точкой повторного разбора (junction, символьная ссылка), иначе отказ. Мастер его не создаёт и не меняет, поэтому подготовить родителя заранее нельзя: обычный пользователь может создать в `ProgramData` подпапку, но не может менять чужую.
2. Папка `%ProgramData%\WXQ-setup-<guid32>` (`CoCreateGuid`) создаётся атомарно (`CreateDir` = `CreateDirectory`, падает, если имя уже есть). Существующая папка (пустая тоже) или файл (в том числе ссылка) с таким именем - отказ; заранее созданную обычным пользователем папку установщик не принимает и не перенастраивает. Владелец новой папки - создатель (у повышенного процесса Администраторы).
3. СРАЗУ `icacls "<папка>" /inheritance:r /grant:r *S-1-5-32-544:(OI)(CI)F *S-1-5-18:(OI)(CI)F`: права только у Администраторов и SYSTEM (по SID, имена зависят от языка Windows), наследование отключено. Код возврата проверяется.
4. Результат проверяется чтением (`SecVerify`): папка не ссылка; `icacls /save` (SDDL, не зависит от языка) даёт защищённый список (флаг `P`) ровно из двух записей «разрешить, `OICI`, `FA`» для `BA` и `SY`; владелец (`GetNamedSecurityInfoW`, без PowerShell) - Администраторы (`WinBuiltinAdministratorsSid`) или SYSTEM (`IsWellKnownSid`); папка пуста (до выдачи прав в неё мог что-то положить посторонний). Не сошлось - папка удаляется, мастер отказывается работать. Та же проверка (ссылка, ACL, владелец) повторяется после копирования файлов, перед каждым запуском `WXQTool.exe` и перед запуском окна.
5. Только после этого копируются `WXQTool.exe`, `install.json` (и `launcher-profiles.json` в сборке с лаунчером); перед записью в игру в ту же папку копируются файлы данных, затем при запуске окна - `WXQSetupUI.exe`. SHA-256 КОПИИ (`GetSHA256OfFile`, Inno 6.2) сверяется с константой, которую `build_installer.py` подставляет в ISCC (`/DToolSha256`, `/DInstallSha256`, `/DUiSha256`, `/DProfilesSha256`; для файлов данных - строки в `payload-copy.iss`). Файлы данных проверяются теми же константами, поэтому подмена `install.json` или пакетов в `{tmp}` до копирования невозможна.
6. `WXQTool.exe` (`--payload`, `--out`, `--progress`) и `WXQSetupUI.exe` (`--dir`) запускаются только оттуда; `state.json`, `commands.jsonl`, `tool-out.txt`, `tool-progress.txt` и шрифты окна лежат в той же папке. `{tmp}` остаётся только источником копирования.
7. В `DeinitializeSetup` (то есть и после успеха, и после сбоя, и после `close`) папка удаляется (`DelTree`, до ~4 с на закрытие окна). Не удалилась - в журнале, ничего страшного. Следующий запуск удаляет остатки только внутри `%ProgramData%`, только папки с именем ровно `WXQ-setup-` + 32 знака `0-9a-f`, не ссылки, с владельцем Администраторы или SYSTEM, старше суток по времени последней записи; чужие имена, ссылки и свежие папки (параллельный запуск) не трогаются.

Отказы:

- Не удалось подготовить папку, права не выставились или не прочитались, SHA-256 копии `WXQTool.exe` или данных не совпал - установщик отказывается работать (`InitializeSetup` возвращает `False`; не в тихом режиме показывает сообщение). Помощника без защищённой папки запустить нельзя ни с окном, ни со стандартными страницами Inno, поэтому «откат на стандартные страницы» здесь не годится: он работал бы с тем же помощником.
- SHA-256 копии `WXQSetupUI.exe` не совпал или окно не скопировалось - копия удаляется, окно не запускается, мастер остаётся на стандартных страницах Inno (помощник при этом уже в защищённой папке).

Тестовая сборка (`--test-build`, `/CURRENTUSER`, без повышения). Права дополнительно включают текущего пользователя (`GetUserNameString`, `icacls` по имени), иначе тест запер бы себя; проверка читает ровно три записи. Этот код стоит только внутри `#ifdef TestBuild` и в релизный скрипт не попадает (проверяют S2, S10, S11 в `run_tests.py` по скрипту после препроцессора ISPP: `build_installer.py --dump-script`, в нём SID только `S-1-5-32-544` и `S-1-5-18`). Параметры только тестовой сборки: `/UISTATEDIR=<папка>` - точный путь защищённой папки (родитель - её каталог; существовать она не должна), `/SECPARENT=<папка>` - родитель вместо `%ProgramData%` (тесты не трогают настоящий ProgramData; в тестовой сборке он создаётся, если его нет), `/SECOWNER=SY` - допустимым владельцем считается только SYSTEM (проверка отказа по владельцу; без параметра тестовая сборка принимает ещё и владельца, совпадающего с владельцем `{tmp}` мастера - текущего пользователя), `/UIEXE=<exe>` - подставное окно, `/UIEXESHA=<sha256>` - эталон для него (без параметра сверки нет), `/TOOLSHA=<sha256>` - неверный эталон помощника для проверки отказа.

Что остаётся (не закрыто этой мерой):

- Владельца установщик не выставляет, а проверяет: Администраторы или SYSTEM, иначе отказ. Если политика заменила владельца повышенного процесса на пользователя, установщик откажется работать, а не продолжит с более слабой защитой.
- Окно между `CreateDir` и `icacls` (папка с унаследованными от `ProgramData` правами, создатель-владелец Администраторы): записать в неё обычный пользователь не может, а то, что окажется внутри, ловит проверка «папка пуста».
- Старый путь `%ProgramData%\Egoist\WXQ-setup-*` не используется и не чистится: остатки прежних сборок, если были, остаются как есть. Данные и копии игры (`%ProgramData%\Egoist\WXQ-Russian`) - отдельный каталог помощника, к защищённой папке установщика отношения не имеет.
- Растры окна мастера (`LoadAsset`) и файлы деинсталлятора по-прежнему идут через `{tmp}`.
- Реальный запрос UAC и настоящий ACL повышенного процесса не проверялись: тесты идут без повышения.
